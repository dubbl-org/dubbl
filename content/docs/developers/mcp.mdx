dubbl has a built-in [Model Context Protocol](https://modelcontextprotocol.io) server. Point an AI client at it, sign in once in your browser, and the agent can look things up and do the work for you: find overdue invoices, draft a bill, categorize bank transactions, run a profit and loss. It acts as you, inside the one organization you choose, with your role's permissions.

The server lives at:

```
https://dubbl.dev/api/mcp
```

If you self-host, use your own address, such as `https://books.example.com/api/mcp`.

## Connect your AI client

<Tabs items={["Claude Code", "Claude desktop and claude.ai", "Cursor", "VS Code", "Other clients"]}>

<Tab value="Claude Code">

```bash
claude mcp add --transport http dubbl https://dubbl.dev/api/mcp
```

Then run `/mcp` inside Claude Code and choose **dubbl** to sign in.

</Tab>

<Tab value="Claude desktop and claude.ai">

Open **Settings**, then **Connectors**, and choose **Add custom connector**. Name it dubbl and paste `https://dubbl.dev/api/mcp` as the URL. Choose **Connect** on the new connector to sign in.

A self-hosted dubbl has to be reachable over public HTTPS for claude.ai to connect to it.

</Tab>

<Tab value="Cursor">

Add this to `.cursor/mcp.json` in your project (or `~/.cursor/mcp.json` for every project):

```json
{
  "mcpServers": {
    "dubbl": { "url": "https://dubbl.dev/api/mcp" }
  }
}
```

</Tab>

<Tab value="VS Code">

Add this to `.vscode/mcp.json` in your workspace:

```json
{
  "servers": {
    "dubbl": { "type": "http", "url": "https://dubbl.dev/api/mcp" }
  }
}
```

</Tab>

<Tab value="Other clients">

Any client that speaks MCP over Streamable HTTP and supports OAuth works. Give it the server URL; it finds everything else from dubbl's `/.well-known` metadata. The endpoints are listed under **Endpoints for client authors** below.

</Tab>

</Tabs>

<Step>

Add the server in your client, as above.

</Step>

<Step>

The client opens dubbl in your browser. Sign in if you aren't already.

</Step>

<Step>

On **Authorize MCP Access**, check what the client is asking for and which organization it gets. If you belong to several, choose one under **Select Organization**.

</Step>

<Step>

Choose **Authorize**. Your browser hands the client a code, the client swaps it for its own tokens, and its dubbl tools appear. **Deny** sends it away with nothing.

</Step>

## Good to know

- One connection works in one organization. To use a second organization, add the server again (with another name) and pick the other one when you authorize.
- The agent can do exactly what your role allows, no more. A member who can't approve bills can't have an agent approve them either.
- The MCP server takes only the tokens it hands out (they start with `mcp_at_`). API keys don't work here.
- Tokens refresh on their own. An access token lasts an hour; the refresh token lasts 30 days and is replaced every time it's used, so a client you use at least once a month stays connected.
- Money in tool inputs follows the same rules as the API: ledger amounts in cents, document line prices as decimals. Each tool's description says which.
- Every plan, including Free, includes MCP access.

## Things to ask

Once connected, talk to it like a bookkeeper who has the books open:

- "Which invoices are overdue, and who owes us the most?"
- "Draft an invoice to Acme Corp for 12 hours of consulting at $150 an hour, due in 14 days."
- "Apply my bank rules to the uncategorized transactions in the checking account, then show me what's left."
- "Run a profit and loss for last quarter and compare it with the same quarter last year."
- "Which bills are due this week, and is there enough in the bank to pay them?"

## Endpoints for client authors

dubbl is an OAuth 2.1 authorization server with PKCE (S256 only), dynamic client registration and public clients (no client secret). The scope is `mcp`.

| Endpoint | Method | What it does |
| --- | --- | --- |
| `/api/mcp` | `POST`, `GET`, `DELETE` | The MCP server (Streamable HTTP). Send `Authorization: Bearer mcp_at_...` |
| `/.well-known/oauth-protected-resource/api/mcp` | `GET` | Protected resource metadata; the `401` from `/api/mcp` points here in `WWW-Authenticate` |
| `/.well-known/oauth-authorization-server` | `GET` | Authorization server metadata |
| `/api/mcp/oauth/register` | `POST` | Register a client: `redirect_uris` (required) and `client_name`. Returns a `client_id` starting with `mcp_` |
| `/api/mcp/oauth/authorize` | `GET` | Start sign-in: `client_id`, `redirect_uri`, `code_challenge`, `code_challenge_method=S256`, `state`, `response_type=code` |
| `/api/mcp/oauth/token` | `POST` | `grant_type=authorization_code` with `code`, `redirect_uri`, `code_verifier`, `client_id`; or `grant_type=refresh_token` with `refresh_token`, `client_id` |

A token response looks like this:

```json
{
  "access_token": "mcp_at_4f1c9a...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "mcp_rt_b82e07...",
  "scope": "mcp"
}
```

Authorization codes last 5 minutes and work once. Refreshing returns a new pair and retires the old refresh token. Tool results come back as JSON text; a failed tool returns `isError: true` with `{"error": "..."}`. The message says what was wrong (a missing record, a locked period, a value that isn't allowed) so the assistant can fix its request. Unexpected server faults come back as `Internal error`, without details.

## Disconnecting a client

There are three ways to cut a client off. Each takes effect on its next call:

- **Your own clients:** open your profile, go to the **Security** tab and choose **Disconnect** next to the client under **Connected AI assistants**.
- **Anyone's client in your organization:** an owner or admin opens **Settings**, then **API Keys**, and chooses **Revoke** next to it under **MCP connections**.
- **Everything at once:** **Revoke all sessions** in the **Security** tab signs you out of every browser, the iOS app and every AI client.

dubbl also checks on every call that the person who connected the client is still a member of the organization, with their current role. If they're removed, the client stops working straight away and can't refresh its token. You can still remove the dubbl server in the client itself (for Claude Code, `claude mcp remove dubbl`).
