The REST API covers everything the app does: more than 500 endpoints under `/api/v1`, grouped by resource. This page maps them, so you can find the one you need and see how the main ones fit together. dubbl doesn't publish an OpenAPI file yet; each endpoint's exact fields are in its route file, and the path tells you where.

Base URL: `https://dubbl.dev/api/v1` (or your own domain if you self-host). Send your [API key](/docs/developers/authentication) on every request, and see [Conventions](/docs/developers/conventions) for cents, dates, pages and errors.

## From draft invoice to paid

The calls behind the most common job, in order.

<Steps>

<Step>

**Create a draft.** Line prices are decimals here; everything that comes back is in cents.

```bash
curl -X POST "https://dubbl.dev/api/v1/invoices" \
  -H "Authorization: Bearer dk_live_q8Xr2LmN4vTz7KpW1sYc9HbJ3fDg6QaE" \
  -H "Content-Type: application/json" \
  -d '{
    "contactId": "5f2c8e14-7a3b-4c19-8d62-1e9b0a7c4f35",
    "issueDate": "2026-10-13",
    "reference": "PO-7781",
    "lines": [
      { "description": "Brand refresh", "quantity": 1, "unitPrice": 4500, "taxRateId": "9d0e5c7a-2b41-4f3e-8a6d-3c5b1e7f9a20" }
    ]
  }'
```

```json
{
  "invoice": {
    "id": "0b7d3a62-58f1-4b8e-9a35-2f6c1d4e8a90",
    "invoiceNumber": "INV-00011",
    "status": "draft",
    "issueDate": "2026-10-13",
    "dueDate": "2026-11-12",
    "subtotal": 450000,
    "taxTotal": 45000,
    "total": 495000,
    "amountDue": 495000,
    "currencyCode": "USD"
  },
  "creditLimitWarning": null
}
```

Leave out `dueDate` and dubbl works it out from the customer's payment terms (or your organization's default).

</Step>

<Step>

**Send it.** With no body, the invoice is marked as sent and recorded in your books, without an email. To email it, send `sendEmail: true` with `recipientEmail`, `subject` and the email's `templateProps`.

```bash
curl -X POST "https://dubbl.dev/api/v1/invoices/0b7d3a62-58f1-4b8e-9a35-2f6c1d4e8a90/send" \
  -H "Authorization: Bearer dk_live_q8Xr2LmN4vTz7KpW1sYc9HbJ3fDg6QaE"
```

</Step>

<Step>

**Record the payment** when the money arrives. This amount is in cents.

```bash
curl -X POST "https://dubbl.dev/api/v1/invoices/0b7d3a62-58f1-4b8e-9a35-2f6c1d4e8a90/pay" \
  -H "Authorization: Bearer dk_live_q8Xr2LmN4vTz7KpW1sYc9HbJ3fDg6QaE" \
  -H "Content-Type: application/json" \
  -d '{ "amount": 495000, "date": "2026-11-02", "method": "bank_transfer", "reference": "Wire 88213" }'
```

```json
{
  "invoice": { "id": "0b7d3a62-58f1-4b8e-9a35-2f6c1d4e8a90", "status": "paid", "amountPaid": 495000, "amountDue": 0 },
  "payment": { "id": "e2a91c3d-...", "paymentNumber": "PAY-00007", "date": "2026-11-02", "amount": 495000, "method": "bank_transfer" }
}
```

`method` is one of `bank_transfer`, `cash`, `check`, `card` or `other`. A smaller amount leaves the invoice `partial`; more than is due is refused.

</Step>

</Steps>

## Reports

Every report is a `GET` under `/reports/` that takes `startDate` and `endDate` (or an as-at date), and many take `basis=cash` or `basis=accrual`. The main statements (profit and loss, balance sheet, cash flow, trial balance, general ledger, aged receivables and payables, sales by customer and by item, tracking categories, executive summary) also take `format=pdf` or `format=xlsx` for a file instead of JSON.

```bash
curl "https://dubbl.dev/api/v1/reports/profit-and-loss?startDate=2026-01-01&endDate=2026-09-30&basis=accrual" \
  -H "Authorization: Bearer dk_live_q8Xr2LmN4vTz7KpW1sYc9HbJ3fDg6QaE"
```

```json
{
  "startDate": "2026-01-01",
  "endDate": "2026-09-30",
  "basis": "accrual",
  "revenue": [{ "accountId": "3c1a...", "accountCode": "4000", "accountName": "Sales", "balance": 6285000 }],
  "totalRevenue": 6285000,
  "expenses": [{ "accountId": "7e42...", "accountCode": "6100", "accountName": "Rent", "balance": 1350000 }],
  "totalExpenses": 2914000,
  "netIncome": 3371000
}
```

The response above is trimmed to one account per section.

The reports: `profit-and-loss`, `income-statement`, `pnl-comparison`, `balance-sheet`, `cash-flow`, `cash-flow-forecast`, `bank-cash-flow`, `trial-balance`, `general-ledger`, `account-transactions`, `aged-receivables`, `aged-payables`, `sales-by-customer`, `sales-by-item`, `vendor-spend`, `expense-analytics`, `budget-vs-actual`, `profitability`, `tracking-category`, `inventory-valuation`, `unrealized-gains-losses`, `financial-ratios`, `executive-summary`, `monthly-trends`, `payment-performance`, `recurring-transactions`, `duplicate-detection`, `financial-calendar`, `bank-reconciliation-status` and `pack`. Saved custom reports live at `/reports/saved` and `POST /reports/run`; schedules at `/report-schedules`.
